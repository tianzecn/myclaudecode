<生成规则>
## 提示词生成规则

生成的提示词必须遵循以下原则：

1. **结构化**: 使用清晰的章节划分
   - 元信息、目的、输入输出、正文、示例、注意事项
   - 层次分明，逻辑清晰

2. **具体化**: 避免模糊描述，使用具体指令
   - 用明确的动词（生成、分析、检查、提取）
   - 避免"适当地"、"合理地"等模糊词汇

3. **可验证**: 包含明确的输出格式和验收标准
   - 定义清晰的成功标准
   - 提供输出示例

4. **边界清晰**: 明确说明能做什么、不能做什么
   - 明确输入范围
   - 说明限制条件
</生成规则>

## 完整示例

**用户需求：**
> 我需要一个代码审查提示词，用于审查 Python 代码的安全性和性能问题。

**生成的提示词：**

```markdown
# Python 代码安全性能审查

## 元信息
- 版本: v1.0
- 标签: [code-review, security, performance, python]

## 目的
审查 Python 代码的安全性和性能问题，提供改进建议。

## 输入
- 必需: Python 代码文件或代码片段
- 可选: 项目上下文、特定关注点

## 输出
结构化的审查报告，包含：
- 安全问题列表（严重程度、位置、建议）
- 性能问题列表（影响程度、位置、优化建议）
- 整体评分和总结

## 提示词正文
```
你是一位资深的 Python 安全和性能专家。请审查以下代码，重点关注：

### 安全性审查
1. 输入验证和消毒
2. SQL 注入、XSS 等注入攻击
3. 敏感数据处理（密码、API密钥）
4. 权限和认证问题
5. 依赖包安全性

### 性能审查
1. 算法复杂度
2. 内存使用效率
3. I/O 操作优化
4. 并发处理
5. 缓存策略

### 输出格式
请按以下格式输出审查结果：

## 安全问题
| 严重程度 | 行号 | 问题描述 | 修复建议 |
|----------|------|----------|----------|
| 高/中/低 | n    | ...      | ...      |

## 性能问题
| 影响程度 | 行号 | 问题描述 | 优化建议 |
|----------|------|----------|----------|
| 高/中/低 | n    | ...      | ...      |

## 总结
- 安全评分: x/10
- 性能评分: x/10
- 优先修复项: [列表]
```

## 使用示例
输入：
```python
import sqlite3

def get_user(username):
    conn = sqlite3.connect('users.db')
    cursor = conn.cursor()
    query = f"SELECT * FROM users WHERE username = '{username}'"
    cursor.execute(query)
    return cursor.fetchone()
```

输出：审查报告显示 SQL 注入高危漏洞...

## 注意事项
- 仅审查提供的代码，不执行代码
- 大型代码库建议分模块审查
- 报告中的修复建议需人工验证后实施
```
</示例>
