# Clean Project

我将帮助清理开发产物,同时保留您的工作代码。

## 战略思考过程

<think>
清理前,我需要仔细考虑:

1. **产物识别**
   - 什么模式表明是临时/调试文件?
   - 哪些文件可能看起来是临时的但实际上很重要?
   - 项目是否有特定的临时文件约定?
   - 应该保留哪些生成的文件?

2. **安全分析**
   - 哪些删除肯定是安全的?
   - 哪些需要更仔细的检查?
   - 是否有活动进程正在使用这些文件?
   - 删除这些会破坏开发环境吗?

3. **常见陷阱**
   - .env 文件可能看起来像产物但包含配置
   - .cache 目录可能是性能所需的
   - 某些 .tmp 文件可能是活动会话数据
   - 调试日志可能包含重要的错误信息

4. **清理策略**
   - 从明显的产物开始 (*.log, *.tmp, *~)
   - 检查文件年龄 - 较旧的文件通常更安全删除
   - 使用 git status 验证跟踪的 vs 未跟踪的
   - 为批量决策分组相似文件
</think>

基于此分析,我将创建一个 git 检查点以确保安全:
```bash
git add -A
git commit -m "Pre-cleanup checkpoint" || echo "No changes to commit"
```

**重要**: 我绝不会:
- 添加 "Co-authored-by" 或任何 Claude 签名
- 包含 "Generated with Claude Code" 或类似消息
- 修改 git config 或用户凭据
- 在提交中添加任何 AI/助手归属
- 在提交、PR 或 git 相关内容中使用表情符号

我将使用原生工具识别清理目标:
- **Glob 工具** 查找临时和调试文件
- **Grep 工具** 检测代码中的调试语句
- **Read 工具** 在删除前验证文件内容

关键目录自动受保护:
- .claude 目录 (命令和配置)
- .git 目录 (版本控制)
- node_modules, vendor (依赖目录)
- 必要的配置文件

当我发现多个要清理的项目时,我将创建待办事项列表以系统地处理它们。

我将在采取行动前向您展示将删除的内容及原因:
- 调试/日志文件和临时产物
- 失败的实现尝试
- 仅供开发的文件
- 代码中的调试语句

清理后,我将验证项目完整性并报告清理的内容。

如果发生任何问题,我可以从开始时创建的 git 检查点恢复。

这样既能保持干净的工作代码,又能保证完全的安全。
