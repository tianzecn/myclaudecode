# Systematically Debug and Fix Errors

系统性调试和修复错误

## 说明

遵循以下全面的调试方法来解决: **$ARGUMENTS**

1. **错误信息收集**
   - 收集完整的错误消息、堆栈跟踪和错误代码
   - 记录错误发生的时间 (时机、条件、频率)
   - 识别错误发生的环境 (dev, staging, prod)
   - 收集错误前后的相关日志

2. **重现错误**
   - 创建能一致重现错误的最小测试用例
   - 记录触发错误所需的确切步骤
   - 如果可能,在不同环境中测试
   - 记录影响错误发生的任何模式或条件

3. **堆栈跟踪分析**
   - 从下到上阅读堆栈跟踪以理解调用链
   - 识别错误起源的确切行
   - 跟踪导致错误的执行路径
   - 查找失败代码中的任何明显问题

4. **代码上下文调查**
   - 检查错误位置周围的代码
   - 检查可能引入bug的最近更改
   - 审查错误时的变量值和状态
   - 分析函数参数和返回值

5. **假设形成**
   - 基于证据,形成关于根本原因的假设
   - 考虑常见原因:
     - 空指针/未定义引用
     - 类型不匹配
     - 竞态条件
     - 资源耗尽
     - 逻辑错误
     - 外部依赖失败

6. **调试工具设置**
   - 为技术栈设置适当的调试工具
   - 根据需要使用调试器、分析器或日志
   - 在战略位置配置断点
   - 如尚未设置,配置监控和告警

7. **系统性调查**
   - 有条理地测试每个假设
   - 使用二分查找方法隔离问题
   - 添加战略性日志或打印语句
   - 逐步检查数据流和转换

8. **数据验证**
   - 验证输入数据格式和有效性
   - 检查边缘情况和边界条件
   - 验证关于数据状态的假设
   - 使用不同数据集测试以隔离模式

9. **依赖分析**
   - 检查外部依赖及其版本
   - 验证网络连接和 API 可用性
   - 审查配置文件和环境变量
   - 测试数据库连接和查询执行

10. **内存和资源分析**
    - 检查内存泄漏或过度内存使用
    - 监控 CPU 和 I/O 资源消耗
    - 如适用,分析垃圾回收模式
    - 检查资源死锁或争用

11. **并发问题调查**
    - 在多线程代码中查找竞态条件
    - 检查同步机制和锁
    - 分析异步操作和 promise 处理
    - 在不同负载条件下测试

12. **根本原因识别**
    - 一旦识别出原因,理解为什么会发生
    - 确定是逻辑错误、设计缺陷还是外部问题
    - 评估问题的范围和影响
    - 考虑其他地方是否存在类似问题

13. **解决方案实施**
    - 设计解决根本原因的修复
    - 考虑多种解决方案方法和权衡
    - 实施具有适当错误处理的修复
    - 在需要的地方添加验证和防御性编程

14. **测试修复**
    - 针对原始错误情况测试修复
    - 测试边缘情况和相关场景
    - 运行回归测试以确保没有新问题
    - 在各种负载和压力条件下测试

15. **预防措施**
    - 添加适当的单元测试和集成测试
    - 改进错误处理和日志记录
    - 添加输入验证和防御性检查
    - 更新文档和代码注释

16. **监控和告警**
    - 为类似问题设置监控
    - 添加指标和健康检查
    - 为错误阈值配置告警
    - 实施更好的可观测性

17. **文档**
    - 记录错误、调查过程和解决方案
    - 更新故障排除指南
    - 与团队分享学习成果
    - 用上下文更新代码注释

18. **解决后审查**
    - 分析为什么错误没有更早被发现
    - 审查开发和测试过程
    - 考虑改进以防止类似问题
    - 如需要,更新编码标准或指南

在整个调试过程中保持详细记录,并考虑错误和修复的更广泛影响。
