## 使命

启动代码库侦探 agent，对复杂代码库执行全面的代码分析、调查和导航。此命令帮助理解代码工作原理、查找特定实现、追踪功能流程并分析架构模式。

## 分析请求

$ARGUMENTS

## 何时使用此命令

在以下情况下使用 `/analyze`：

- **理解架构**：身份验证是如何实现的？数据库层结构是什么？
- **查找实现**：用户注册逻辑在哪里？哪个文件处理支付？
- **追踪功能**：从 API 端点到数据库的流程追踪
- **调试问题**：登录为什么不工作？这个错误来自哪里？
- **查找模式**：所有 API 调用在哪里进行？哪些组件使用 Redux？
- **分析依赖**：什么使用了这个服务？这个工具在哪里被导入？

## 工作原理

此命令启动 **codebase-detective** agent，它会：

1. 在可用时使用语义代码搜索（claudemem CLI）
2. 需要时回退到标准 grep/find/rg 工具
3. 跨文件追踪导入和依赖
4. 分析代码结构和模式
5. 提供精确的文件位置和行号
6. 解释代码关系和流程

## 指令

### 步骤 1：理解请求

从 $ARGUMENTS 解析用户的分析请求：

- 他们试图理解什么？
- 他们在寻找什么特定的代码/功能？
- 上下文是什么（调试、学习、重构）？

### 步骤 2：启动 codebase-detective Agent

使用 Task 工具启动 agent：

```
Task(
  subagent_type: "code-analysis:detective",
  description: "Analyze codebase for [简要描述]",
  prompt: `
    在代码库中调查以下内容：

    [来自 $ARGUMENTS 的用户分析请求]

    工作目录：[当前工作目录]

    请提供：
    1. 带行号的精确文件位置
    2. 显示实现的代码片段
    3. 代码如何工作的解释
    4. 相关文件和依赖
    5. 如果复杂，提供代码流程/架构图

    如果可用，使用语义搜索（claudemem CLI），否则
    使用 grep/ripgrep/find 进行模式匹配。
  `
)
```

### 步骤 3：呈现结果

在 agent 完成后：

1. **总结发现**：关键文件、主要实现位置
2. **显示代码结构**：组件之间如何关联
3. **提供后续步骤**：关于如何使用这些信息的建议
4. **提供后续**：询问是否需要对特定部分进行更深入的分析

## 使用示例

### 示例 1：查找身份验证逻辑

```
用户：/analyze 用户身份验证在哪里处理？

Agent 启动提示：
"查找并解释身份验证实现。包括：
- 登录端点/处理程序
- 令牌生成/验证
- 身份验证中间件
- 会话管理
- 相关安全代码"

结果：
- src/auth/login.handler.ts:23-67 (登录端点)
- src/middleware/auth.middleware.ts:12-45 (JWT 验证)
- src/services/token.service.ts:89-120 (令牌生成)
```

### 示例 2：追踪 Bug

```
用户：/analyze 用户资料页面在电子邮件字段显示"undefined"

Agent 启动提示：
"追踪用户资料电子邮件显示问题：
1. 找到资料页面组件
2. 定位电子邮件数据的获取位置
3. 检查电子邮件如何传递给组件
4. 识别'undefined'可能被引入的位置"

结果：
- 在 ProfilePage.tsx:156 中发现缺少 null 检查
- 发现 API 返回'e-mail'但代码期望'email'
- 提供了不匹配的精确行号
```

### 示例 3：理解架构

```
用户：/analyze 支付处理流程如何工作？

Agent 启动提示：
"绘制完整的支付处理流程：
1. 入口点（API 端点或 UI 触发器）
2. 验证和业务逻辑
3. 支付网关集成
4. 数据库持久化
5. 成功/失败处理
6. 相关服务和工具"

结果：
- 从结账按钮到确认的流程图
- 涉及的 7 个关键文件及其作用
- 外部依赖（Stripe SDK）
- 错误处理策略
```

## 有效分析技巧

1. **具体明确**：不要说"分析代码库"，而是问"电子邮件验证逻辑在哪里？"
2. **提供上下文**：说明你是在调试、重构还是学习
3. **进行后续提问**：在初始结果后，深入特定文件
4. **用于导航**：快速熟悉不熟悉的代码库

```

2. 处理：[文件:行]
3. 结果：[文件:行]

**相关组件**：
- [组件名称] - [用途]
- [服务名称] - [用途]

**如何导航**：
[进一步探索代码的命令]

**建议**：
[基于分析的建议]
```

## 成功标准

当满足以下条件时命令成功：

1. ✅ 用户的问题通过精确位置得到完全回答
2. ✅ 代码关系和流程得到清晰解释
3. ✅ 提供了文件路径和行号
4. ✅ 用户可以导航到代码并理解它
5. ✅ 预测并解决了后续问题

## 注意事项

- codebase-detective agent 针对速度和准确性进行了优化
- 它将使用最佳可用工具（claudemem 搜索或 grep/ripgrep）
- 结果包含可操作的后续步骤
- 可以处理复杂的多文件调查
- 非常适合新代码库的入职
- claudemem 需要 OpenRouter API 密钥 (https://openrouter.ai)
- 运行 `claudemem --models` 查看嵌入模型选项和定价
