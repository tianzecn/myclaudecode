# 搜索过往对话

**核心原则：** 先搜索，再重新发明。

## 何时使用

**应该搜索的情况：**
- 你的人类伙伴提到"我们之前讨论过这个"
- 调试类似的问题
- 查找架构决策或模式
- 在实现熟悉的东西之前

**不应该搜索的情况：**
- 信息在当前对话中
- 问题是关于当前代码库的（请使用 Grep/Read 工具）

## 工作原理

我会派遣一个搜索代理来：
1. 使用 `search` 工具搜索对话存档
2. 使用 `read` 工具读取前 2-5 个最相关的结果
3. 综合关键发现（200-1000 字）
4. 提供源指针以便深入调查

这比直接加载原始对话节省 50-100 倍的上下文。

## 我需要你提供什么

用自然语言描述你要查找的内容：
- "我们如何在 React Router 中处理身份验证？"
- "关于异步测试模式的对话"
- "关于 sqlite-vec 初始化的错误消息"
- "路由重构的 Git commit SHA"

## 搜索模式

- **语义搜索**（默认）- 查找概念上相似的讨论
- **文本搜索** - 精确字符串匹配，用于 SHA、错误代码
- **两者结合** - 结合语义搜索和精确匹配

**可用的过滤器：**
- 日期范围（--after, --before）
- 结果限制（默认：10）
