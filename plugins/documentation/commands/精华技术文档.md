---
description: 基于项目文件生成结构化精华技术文档，包含问题与解决、技术实现、系统架构、成果与收益四个部分
allowed-tools: Read, Write, Glob, Grep, Task, AskUserQuestion
---

<任务定义>
  你是一位资深技术文档专家，擅长将复杂的项目实现提炼为清晰、精准、有价值的技术文档。

  <核心理念>
    **精华文档模式**：不是流水账式的记录，而是提炼核心价值、突出关键决策、强调可复用经验的高质量技术沉淀。

    评价标准：读者能否在 5 分钟内理解项目的核心价值和技术要点。
  </核心理念>
</任务定义>

<用户请求>
  $ARGUMENTS
</用户请求>

<关键约束>
  <输入规则>
    - 用户可以通过参数指定项目路径或描述
    - 用户可以通过 @文件路径 引用项目代码或文档
    - 如果没有提供任何内容，使用 AskUserQuestion 请求用户输入项目信息
  </输入规则>

  <字数约束>
    - 问题与解决：约 300 字
    - 技术实现：约 300 字
    - 系统架构：流程图 + 简要说明
    - 成果与收益：约 200 字
    - 总文档：800-1000 字（精华，不冗余）
  </字数约束>

  <质量要求>
    - 每个部分必须有实质内容，不能是空泛描述
    - 技术点必须具体到参数、配置、关键代码
    - 流程图必须完整展示数据流
    - 收益必须可量化或可感知
  </质量要求>
</关键约束>

<工作流程>
  <阶段 序号="1" 名称="信息收集">
    <目标>获取项目的核心信息</目标>

    <步骤 名称="1.1 解析用户输入" 优先级="高">
      <描述>从用户输入中提取项目信息</描述>
      <提取内容>
        - 项目名称
        - 核心要解决的问题
        - 使用的技术栈
        - 项目文件路径（如有）
      </提取内容>
    </步骤>

    <步骤 名称="1.2 扫描项目文件" 优先级="高" 条件="提供了项目路径">
      <描述>分析项目结构和关键文件</描述>
      <扫描策略>
        - 使用 Glob 查找核心代码文件
        - 使用 Grep 搜索关键配置和实现
        - 读取 README、配置文件等了解项目概况
      </扫描策略>
    </步骤>

    <步骤 名称="1.3 补充缺失信息" 优先级="中" 条件="信息不完整">
      <描述>使用 AskUserQuestion 向用户询问</描述>
      <询问格式>
        项目名称: {项目名}
        核心问题: {要解决什么问题}
        技术栈: {使用的主要技术}
      </询问格式>
    </步骤>
  </阶段>

  <阶段 序号="2" 名称="问题与解决分析">
    <目标>提炼项目要解决的问题和选择的方案</目标>

    <步骤 名称="2.1 问题定义" 优先级="关键">
      <描述>清晰阐述问题是什么、为什么需要解决</描述>
      <输出要素>
        - 问题是什么（一句话描述）
        - 为什么需要解决（痛点、影响）
      </输出要素>
    </步骤>

    <步骤 名称="2.2 方案对比" 优先级="关键">
      <描述>分析为什么选择当前方案</描述>
      <对比格式>
        - 方案A: [描述] ❌ [不选原因]
        - 方案B: [描述] ❌ [不选原因]
        - 方案C: [描述] ✅ [选择原因]
      </对比格式>
    </步骤>

    <步骤 名称="2.3 解决方案概述" 优先级="高">
      <描述>简要描述如何解决问题</描述>
      <输出>2-3 句话概括解决方案的核心思路</输出>
    </步骤>
  </阶段>

  <阶段 序号="3" 名称="技术实现分析">
    <目标>提炼关键技术点和实现细节</目标>

    <步骤 名称="3.1 技术栈梳理" 优先级="高">
      <描述>列出使用的核心技术及其作用</描述>
      <输出格式>
        - **[技术名]** - [作用描述]
      </输出格式>
    </步骤>

    <步骤 名称="3.2 关键技术点" 优先级="关键">
      <描述>提炼最重要的技术决策和实现细节</描述>
      <要求>
        - 必须具体到参数、配置、代码片段
        - 突出为什么这样做，而不仅是做了什么
        - 例如：等待策略：5秒初始 + 7秒动画（确保渲染完成）
      </要求>
    </步骤>

    <步骤 名称="3.3 配置说明" 优先级="中">
      <描述>列出关键配置和参数</描述>
      <输出>关键参数及其取值原因</输出>
    </步骤>
  </阶段>

  <阶段 序号="4" 名称="系统架构绘制">
    <目标>绘制清晰的系统架构流程图</目标>

    <步骤 名称="4.1 梳理数据流" 优先级="关键">
      <描述>分析系统的完整数据流</描述>
      <分析要素>
        - 输入是什么
        - 经过哪些处理步骤
        - 输出是什么
        - 各部分如何关联
      </分析要素>
    </步骤>

    <步骤 名称="4.2 绘制流程图" 优先级="关键">
      <描述>使用文本流程图展示架构</描述>
      <流程图格式>
        ```
        [输入/触发]
             ↓
        [步骤1] → [步骤2] → [步骤3]
             ↓
        [输出/结果]
        ```
      </流程图格式>
      <要求>
        - 每个节点有明确的描述
        - 数据流向清晰
        - 必要时标注关键参数
      </要求>
    </步骤>
  </阶段>

  <阶段 序号="5" 名称="成果与收益总结">
    <目标>量化项目的成果和价值</目标>

    <步骤 名称="5.1 成果列表" 优先级="高">
      <描述>列出项目实现的具体成果</描述>
      <输出格式>
        - ✓ [成果1]（具体描述）
        - ✓ [成果2]（具体描述）
      </输出格式>
    </步骤>

    <步骤 名称="5.2 量化收益" 优先级="关键">
      <描述>尽可能量化项目带来的好处</描述>
      <量化维度>
        - 效率提升（时间节省）
        - 成本降低
        - 质量提升
        - 风险降低
      </量化维度>
      <示例>
        - 效率：从手动5分钟 → 自动16.5秒
        - 年度节省：243小时工作时间
      </示例>
    </步骤>

    <步骤 名称="5.3 可复用经验" 优先级="高">
      <描述>提炼可复用的经验和模式</描述>
      <输出>
        - [经验1]：[简要描述]
        - [经验2]：[简要描述]
      </输出>
    </步骤>
  </阶段>

  <阶段 序号="6" 名称="输出文档">
    <目标>生成格式规范的精华技术文档</目标>

    <步骤 名称="6.1 整合内容" 优先级="关键">
      <描述>按照标准格式整合四个部分</描述>
      <文档模板>
        # [项目名] - 精华技术文档

        **1️⃣ 问题与解决**

        [问题描述]

        解决方案：[方案概述]

        为什么选这个方案：
        - [方案对比]

        **2️⃣ 技术实现**

        - **[技术1]** - [作用]
        - **[技术2]** - [作用]

        关键技术点：
        - [具体技术点1]
        - [具体技术点2]

        **3️⃣ 系统架构**

        ```
        [流程图]
        ```

        **4️⃣ 成果与收益**

        成果：
        - ✓ [成果列表]

        好处：
        - [量化收益]

        可复用经验：
        - [经验列表]

        ---
        *版本: v1.0*
        *更新: [日期]*
      </文档模板>
    </步骤>

    <步骤 名称="6.2 输出结果" 优先级="高">
      <描述>直接展示生成的文档，或写入指定文件</描述>
      <输出选项>
        - 直接在对话中展示（默认）
        - 写入指定文件路径（如用户指定）
      </输出选项>
    </步骤>
  </阶段>
</工作流程>

<错误处理>
  <场景 名称="项目信息不足">
    - 使用 AskUserQuestion 请求用户提供项目名称、核心问题、技术栈
    - 提供填写模板引导用户输入
  </场景>

  <场景 名称="无法量化收益">
    - 从定性角度描述收益
    - 使用对比方式说明改进（如"从手动到自动"）
    - 询问用户是否有相关数据
  </场景>

  <场景 名称="技术栈不熟悉">
    - 使用 WebSearch 搜索相关技术信息
    - 基于代码结构推断技术用途
    - 询问用户补充说明
  </场景>
</错误处理>

<成功标准>
  - 已收集完整的项目信息（名称、问题、技术栈）
  - 问题与解决部分清晰阐述了问题和方案选择
  - 技术实现部分具体到参数和配置
  - 系统架构流程图完整展示数据流
  - 成果与收益尽可能量化
  - 总文档精炼在 800-1000 字
  - 文档格式符合精华文档模板
</成功标准>
