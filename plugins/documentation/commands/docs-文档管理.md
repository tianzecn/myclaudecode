# 文档管理器

我将通过分析实际发生的情况智能管理你的项目文档，并相应更新所有相关文档。

**我的方法：**
1. **分析整个对话** - 理解变更的完整范围
2. **读取所有文档文件** - README、CHANGELOG、docs/*、指南等
3. **识别变更内容** - 功能、架构、bug、性能、安全等
4. **更新所有受影响的内容** - 不仅仅是一个文件，而是所有相关文档
5. **保持一致性** - 确保所有文档讲述相同的故事

**我不会做假设** - 我会查看实际变更并相应更新。
如果你重构了整个架构，我会更新架构文档、README、迁移指南、API 文档以及任何其他受影响的内容。

## 模式 1：文档概览（默认）

当你不带上下文运行 `/docs` 时，我会：
- **Glob** 所有 markdown 文件（README、CHANGELOG、docs/*）
- **读取** 每个文档文件
- **分析** 文档覆盖率
- **呈现** 组织化的摘要

输出格式：
```
文档概览
├── README.md - [状态：当前/过时]
├── CHANGELOG.md - [最后更新：日期]
├── CONTRIBUTING.md - [完整度：85%]
├── docs/
│   ├── API.md - [状态]
│   └── architecture.md - [状态]
└── 总覆盖率：X%

关键发现
- 缺失：设置说明
- 过时：API 端点（3 个新端点）
- 不完整：测试指南
```

## 模式 2：智能更新

当你运行 `/docs update` 或在实现后，我会：

1. **运行 `/understand`** 分析当前代码库
2. **比较** 代码实际情况 vs 文档
3. **识别** 需要更新的内容：
   - 未记录的新功能
   - 已更改的 API 或接口
   - 文档中仍存在的已删除功能
   - 新的配置选项
   - 更新的依赖项

4. **系统化更新：**
   - README.md 包含新功能/变更
   - CHANGELOG.md 包含版本条目
   - API 文档包含新端点
   - 配置文档包含新选项
   - 如有破坏性变更，更新迁移指南

## 模式 3：会话文档

在长时间编码会话后运行，我会：
- **分析对话历史**
- **列出所有变更**
- **按功能/修复/增强分组**
- **更新适当的文档**

更新将遵循你项目的文档风格和约定，按类型（添加、修复、变更等）在适当的部分组织变更。

## 模式 4：上下文感知更新

基于会话中发生的事情：
- **新功能后**：更新 README 功能，添加到 CHANGELOG
- **bug 修复后**：在 CHANGELOG 中记录，更新故障排除
- **重构后**：更新架构文档、迁移指南
- **安全修复后**：更新安全策略、CHANGELOG
- **性能改进后**：更新基准测试、CHANGELOG

## 智能文档规则

1. **保留自定义内容** - 永远不覆盖手动添加的内容
2. **匹配现有样式** - 遵循当前文档格式
3. **语义部分** - 添加到正确的部分
4. **版本意识** - 在 CHANGELOG 中尊重语义化版本
5. **链接更新** - 修复损坏的内部链接

## 与命令集成

与以下命令无缝协作：
- `/understand` - 首先获取当前架构
- `/contributing` - 更新贡献指南
- `/test` - 记录测试覆盖率变更
- `/scaffold` - 添加新组件文档
- `/security-scan` - 更新安全文档

## 文档规则

**始终：**
- 在任何更新前完整读取现有文档
- 找到需要更新的确切部分
- 就地更新，永不重复
- 保留自定义内容和格式
- 只在绝对必要时创建新文档（缺少 README 等）

**保留部分：**
```markdown
<!-- CUSTOM:START -->
保留用户的手动内容
<!-- CUSTOM:END -->
```

**智能 CHANGELOG：**
- 按类型分组变更
- 建议版本升级（主要/次要/补丁）
- 链接到相关 PR/issue
- 保持时间顺序

**重要**：我永远不会：
- 删除现有文档
- 覆盖自定义部分
- 大幅改变文档样式
- 添加 AI 归属标记
- 创建不必要的文档

分析后，我会问："我们应该如何进行？"
- 更新所有过时的文档
- 专注于特定文件
- 创建缺失的文档
- 生成迁移指南
- 跳过某些部分

## 其他场景和集成

### 何时使用 /docs

在任何重要工作后简单运行 `/docs`：
- `/understand` 后 - 确保文档与代码实际情况匹配
- `/fix-todos` 或 bug 修复后 - 更新所有受影响的文档
- `/scaffold` 或新功能后 - 记录添加的内容
- `/security-scan` 或 `/review` 后 - 记录发现和决策
- 主要重构后 - 更新架构、迁移指南等

**我会根据实际发生的情况确定需要更新什么，而不是僵化的规则。**

### 文档类型
我可以管理：
- **API 文档** - 端点、参数、响应
- **数据库 Schema** - 表、关系、迁移
- **配置** - 环境变量、设置
- **部署** - 设置、要求、程序
- **故障排除** - 常见问题和解决方案
- **性能** - 基准测试、优化指南
- **安全** - 策略、最佳实践、事件响应

### 智能功能
- **版本检测** - 自动递增版本号
- **破坏性变更警报** - 当文档需要迁移指南时警告
- **交叉引用** - 更新文档之间的链接
- **示例生成** - 从测试创建使用示例
- **图表更新** - 更新架构图（基于文本）
- **依赖跟踪** - 记录外部服务要求

### 团队协作
- **PR 文档** - 为拉取请求生成文档
- **发布说明** - 从 CHANGELOG 创建发布内容
- **入职文档** - 从项目分析生成
- **交接文档** - 更换团队时创建
- **知识转移** - 离开项目前记录

### 质量检查
- **文档覆盖率** - 报告未记录的功能
- **新鲜度检查** - 标记过时的文档
- **一致性** - 确保跨文档的统一样式
- **完整性** - 验证所有部分都存在
- **准确性** - 比较文档 vs 实际实现

### 智能命令组合

**分析代码后：**
```bash
/understand && /docs
# 分析整个代码库，然后更新文档以匹配实际情况
```

**修复技术债务后：**
```bash
/fix-todos && /test && /docs
# 修复 TODO，验证一切正常，记录变更
```

**主要重构后：**
```bash
/fix-imports && /format && /docs
# 修复导入，格式化代码，更新架构文档
```

**创建 PR 前：**
```bash
/review && /docs
# 审查代码，然后确保文档反映发现的任何问题
```

**添加功能后：**
```bash
/scaffold component && /test && /docs
# 创建组件，测试它，记录新 API
```

### 简单使用

只需运行 `/docs`，我会弄清楚你需要什么：
- 新项目？我会显示存在哪些文档
- 刚编码？我会更新相关文档
- 长会话？我会记录所有内容
- 刚修复 bug？我会更新 CHANGELOG

无需记住参数 - 我理解上下文！

这使你的文档与代码保持同步，同时支持你的整个开发生命周期。
