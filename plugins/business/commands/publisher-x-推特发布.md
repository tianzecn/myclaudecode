# X/Twitter 推文串生成器

从任何内容源生成可复制粘贴的 X 推文串 - 博客文章、文章、PDF、URL 或纯文本。

**用法:** `$ARGUMENTS`

**处理流程:**

1. **解析输入参数**
   - 提取内容输入和可选语言参数
   - 示例:
     - `2025-10-06-my-post` (仅 slug,默认英文)
     - `2025-10-06-my-post ja` (slug 带日文)
     - `path/to/article.md` (文件路径)
     - `https://myblog.com/post` (URL)
     - `docs/whitepaper.pdf en` (PDF 带语言)

2. **通用输入检测**

   **如果输入看起来像文件路径**(包含 `/` 或文件扩展名):
   - 使用 Read 工具检查文件是否存在
   - 根据扩展名检测格式:
     - `.md` / `.mdx` → 解析带 frontmatter 的 markdown(提取标题、描述、正文、元数据)
     - `.pdf` → 告知用户 PDF 解析有限,建议先转换为 markdown
     - `.docx` → 告知用户 DOCX 解析有限,建议先转换为 markdown
     - `.html` → 读取并提取主要内容,去除 HTML 标签
     - `.txt` → 作为纯文本读取
     - `.json` → 解析 JSON 并提取相关字段
   - 提取: 标题、描述、正文内容、元数据

   **如果输入看起来像 URL**(以 `http://` 或 `https://` 开头):
   - 使用 WebFetch 工具获取页面
   - 提示: "从此页面提取主要文章内容、标题和描述"
   - 解析并清理文本

   **如果输入是 slug**(没有 `/` 且没有协议):
   - 使用 Glob 搜索代码库: `**/*${input}*.md`
   - 要检查的常见模式:
     - `src/content/blog/posts/{en,ja}/*${input}*.md`
     - `content/blog/*${input}*.md`
     - `posts/*${input}*.md`
     - `blog/*${input}*.md`
   - 如果指定了语言,优先匹配语言文件夹
   - 使用 Read 工具解析带 frontmatter 的 markdown 文件

3. **确定语言**(默认: 英文):
   - 如果用户明确指定 "ja" → 日文
   - 如果用户明确指定 "en" → 英文
   - 如果文件路径包含 `/ja/` → 日文
   - 如果内容看起来是日文 → 日文
   - 否则 → 英文

4. **生成三个版本**,使用目标语言:

   **版本1: 推文串(5-8条推文)**
   - 专业且引人入胜的语气
   - 分解为易消化的推文(每条最多280字符)

   **版本2: 单条长文(Premium)**
   - 带有清晰章节的结构化格式
   - **日文**: 使用【括号】: 【とは】【誰のため】【主な特徴】【次にすべきこと】
   - **英文**: 使用标题: **What it is:** **Who it's for:** **Key features:** **What to do next:**

   **版本3: 单条短文(约280字符)**
   - 简洁的公告
   - 2-3个关键优势,带表情符号
   - 链接和话题标签

5. **在终端显示所有版本**:
   - 显示推文串,带字符计数
   - 显示单条长文版本
   - 显示单条短文版本
   - 格式化以便于复制粘贴

6. **使用 Write 工具创建三格式 HTML 预览文件**:
   - **重要**: 首先检查文件是否存在: `ls -la x-thread-[LANG].html 2>&1`
   - 如果文件存在,先使用 Read 工具(即使只读1行): `Read('x-thread-[LANG].html', limit=1)`
   - 然后使用 Write 工具创建/更新: 在用户当前目录中的 `x-thread-[LANG].html`
   - **包含三个标签页和标签切换器 UI**:
     - **标签1: 推文串** - 5-8条推文,每条带独立"复制推文"按钮
     - **标签2: 单条长文** - 带章节的结构化格式,一个"复制"按钮
     - **标签3: 单条短文** - 简洁版本(约280字符),一个"复制"按钮
   - 使用 X 品牌(黑色主题)
   - 顶部标签切换器,便于导航
   - 使用 Bash 工具打开: `open x-thread-[LANG].html && open https://x.com/compose/post`

## X 推文串指南

### 推文串结构(5-8条推文):

1. **钩子推文**(推文 1/X)
   - 用反常规陈述、统计数据或大胆主张吸引注意力
   - 不要透露所有内容 - 制造好奇心
   - 第一条推文中不要使用话题标签或链接(更好的算法覆盖)
   - 最多280字符,包括推文串指示器

2. **问题/背景推文**(推文 2-3/X)
   - 设置问题或背景
   - 使用博客中的具体数据点
   - 每条推文保持一个想法
   - 每条最多280字符

3. **见解推文**(推文 4-6/X)
   - 分享博客中的3-5个关键见解
   - 使用项目符号(•)或编号列表
   - 包含具体示例或统计数据
   - 使每条推文独立完整
   - 每条最多280字符

4. **行动号召推文**(最后一条推文)
   - 链接到完整文章
   - 简单的行动号召: "阅读完整指南:" 或 "完整分析:"
   - 这里可以包含2-3个相关话题标签
   - 鼓励互动: "你怎么看?"

**推文串编号:**
- 在每条推文中包含 "(1/6)" 样式编号
- 计数必须准确
- 放在每条推文末尾

**字符限制:**
- 每条推文: 最多280字符(包括推文串编号)
- 考虑 URL 缩短: X 上 URL = 23字符
- 留出10-15字符的安全缓冲
