# 优化构建命令

优化构建流程和速度

## 说明

按照以下系统化方法优化构建性能:**$ARGUMENTS**

1. **构建系统分析**
   - 识别使用的构建系统 (Webpack、Vite、Rollup、Gradle、Maven、Cargo 等)
   - 审查构建配置文件和设置
   - 分析当前构建时间和输出大小
   - 映射完整的构建管道和依赖关系

2. **性能基线**
   - 测量不同场景的当前构建时间:
     - 清洁构建 (从头开始)
     - 增量构建 (带缓存)
     - 开发环境 vs 生产环境构建
   - 记录包大小和资源大小
   - 识别构建过程中最慢的部分

3. **依赖优化**
   - 分析构建依赖及其影响
   - 从构建过程中移除未使用的依赖
   - 将构建工具更新到最新稳定版本
   - 考虑替代、更快的构建工具

4. **缓存策略**
   - 启用并优化构建缓存
   - 为 CI/CD 配置持久缓存
   - 为团队开发设置共享缓存
   - 在可能的情况下实现增量编译

5. **包分析**
   - 分析包组成和大小
   - 识别大型依赖和重复项
   - 使用特定于构建工具的包分析器
   - 寻找分割包的机会

6. **代码分割和懒加载**
   - 实现动态导入和代码分割
   - 为 SPA 设置基于路由的分割
   - 配置 vendor chunk 分离
   - 优化分块大小和加载策略

7. **资源优化**
   - 优化图片 (压缩、格式转换、懒加载)
   - 压缩 CSS 和 JavaScript
   - 配置 tree shaking 以移除死代码
   - 实现资源压缩 (gzip、brotli)

8. **开发构建优化**
   - 启用快速刷新/热重载
   - 使用开发特定的优化
   - 配置 source map 以便更好地调试
   - 优化开发服务器设置

9. **生产构建优化**
   - 启用所有生产优化
   - 配置死代码消除
   - 设置适当的压缩和优化
   - 针对更小的包大小进行优化

10. **并行处理**
    - 在支持的情况下启用并行处理
    - 为构建任务配置工作线程
    - 针对多核系统优化
    - 对 TypeScript/Babel 使用并行编译

11. **文件系统优化**
    - 优化文件监视和轮询
    - 配置适当的 include/exclude 模式
    - 使用高效的文件加载器和处理器
    - 最小化文件 I/O 操作

12. **CI/CD 构建优化**
    - 优化 CI 构建环境和资源
    - 为 CI 实现适当的缓存策略
    - 高效使用构建矩阵
    - 在有益的情况下配置并行 CI 作业

13. **内存使用优化**
    - 在构建期间监控和优化内存使用
    - 为构建工具配置堆大小
    - 识别并修复构建过程中的内存泄漏
    - 使用内存高效的编译选项

14. **输出优化**
    - 配置压缩和编码
    - 优化文件命名和哈希策略
    - 设置适当的资源清单
    - 实现高效的资源服务

15. **监控和分析**
    - 设置构建时间监控
    - 使用构建分析工具识别瓶颈
    - 跟踪随时间变化的包大小
    - 监控构建性能回归

16. **工具特定优化**

    **对于 Webpack:**
    - 配置 optimization.splitChunks
    - 使用 thread-loader 进行并行处理
    - 启用 optimization.usedExports 进行 tree shaking
    - 配置 resolve.modules 和 resolve.extensions

    **对于 Vite:**
    - 配置 build.rollupOptions
    - 使用 esbuild 进行更快的转译
    - 优化依赖预打包
    - 配置 build.chunkSizeWarningLimit

    **对于 TypeScript:**
    - 使用增量编译
    - 配置项目引用
    - 优化 tsconfig.json 设置
    - 在适当时使用 skipLibCheck

17. **环境特定配置**
    - 分离开发和生产配置
    - 使用环境变量进行构建优化
    - 为条件构建配置功能标志
    - 针对目标环境优化

18. **测试构建优化**
    - 测试构建输出的正确性
    - 在目标环境中验证所有优化工作
    - 检查优化是否有任何破坏性更改
    - 测量并记录性能改进

19. **文档和维护**
    - 记录所有优化更改及其影响
    - 创建构建性能监控仪表板
    - 为构建性能回归设置告警
    - 定期审查和更新构建配置

专注于为您的特定项目和团队工作流提供最大影响的优化。始终在优化前后进行测量以量化改进。
