# 优化打包大小

减少并优化打包大小:**$ARGUMENTS**

## 说明

1. **打包分析和评估**
   - 使用 webpack-bundle-analyzer 或类似工具分析当前打包大小和组成
   - 识别所有包中的大型依赖和未使用代码
   - 评估当前构建配置和优化设置
   - 创建优化跟踪的基线测量
   - 记录当前性能指标和加载时间

2. **构建工具配置**
   - 为生产构建配置构建工具优化设置
   - 启用代码分割和分块优化功能
   - 配置 tree shaking 和死代码消除
   - 设置包分析器和可视化工具
   - 优化构建性能和输出大小

3. **代码分割和懒加载**
   - 为单页应用实现基于路由的代码分割
   - 为组件和模块设置动态导入
   - 配置非关键资源的懒加载
   - 优化分块大小和加载策略
   - 实现渐进式加载模式

4. **Tree Shaking 和死代码消除**
   - 配置构建工具以实现最优 tree shaking
   - 在适当的情况下将包标记为无副作用
   - 优化导入语句以实现更好的 tree shaking
   - 尽可能使用 ES6 模块并避免 CommonJS
   - 实现 babel 插件以自动优化导入

5. **依赖优化**
   - 分析和审计包依赖的大小影响
   - 用更小的替代品替换大型库
   - 使用特定导入而不是导入整个库
   - 实现依赖去重策略
   - 配置外部依赖和 CDN 使用

6. **资源优化**
   - 通过压缩和格式转换优化图片
   - 实现响应式图片加载策略
   - 配置资源压缩和优化
   - 设置高效的文件加载器和处理器
   - 优化字体加载和子集化

7. **模块联邦和微前端**
   - 为大型应用实现模块联邦
   - 配置共享依赖和运行时优化
   - 为代码共享设置微前端架构
   - 优化远程模块加载和缓存
   - 实现联邦性能监控

8. **性能监控和测量**
   - 设置打包大小监控和跟踪
   - 在 CI/CD 中配置自动化包分析
   - 监控随时间变化的打包大小
   - 设置性能预算和告警
   - 跟踪加载性能指标

9. **渐进式加载策略**
   - 实现资源提示 (preload、prefetch、dns-prefetch)
   - 为缓存策略配置 service worker
   - 为懒加载设置 intersection observer
   - 优化关键资源加载优先级
   - 基于连接速度实现自适应加载

10. **验证和持续监控**
    - 在 CI/CD 中设置自动化包大小验证
    - 配置打包大小阈值和告警
    - 实现打包大小回归测试
    - 监控真实世界的加载性能
    - 设置自动化优化建议

专注于在保持应用功能的同时提供最显著打包大小减少的优化。始终测量更改对打包大小和运行时性能的影响。
