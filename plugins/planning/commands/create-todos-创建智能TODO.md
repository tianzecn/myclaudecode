# 创建智能 TODOs

我将分析最近的操作并在你的代码中创建上下文相关的 TODO 注释。

首先，让我了解你的项目标准：
- **Read** README.md 了解项目约定
- **Read** CONTRIBUTING.md 了解代码风格指南
- **Grep** 现有 TODOs 以匹配你的格式
- **Read** 文档以了解技术上下文

我将检查会话中刚刚发生的事情：
- 需要修复的安全扫描发现
- 需要关注的测试失败
- 需要解决的代码审查问题
- 已识别的架构改进
- 建议的性能优化

使用原生工具分析上下文：
- **Grep 工具**查找相关代码部分
- **Read 工具**了解实现细节
- **TodoWrite** 跟踪我正在创建的 TODOs

对于每个 TODO，我将：
1. 找到它所属的确切位置
2. 分析周围代码以了解上下文
3. 创建清晰、可操作的 TODO 注释
4. 包含优先级和类别标记

**TODO 格式适配：**
我将匹配你项目现有的 TODO 风格：
- 检查是否使用类别，如 `[Security]` 或 `(SECURITY)`
- 匹配注释风格：`//`、`#`、`/* */` 等
- 遵循项目使用的任何工单引用模式
- 遵守代码检查器的行长度限制

**智能上下文引用：**
我将创建引用问题来源的 TODOs：
- 安全发现将引用扫描行号
- 性能问题将包含测量的阈值
- Bug 修复将引用失败测试的位置
- 重构需求将引用架构模式

我将使用智能放置：
- 在易受攻击的代码附近放置安全 TODOs
- 在瓶颈位置放置性能 TODOs
- 在错误发生处放置 Bug 修复
- 在集成点放置架构 TODOs

创建 TODOs 后，我将询问："你想如何跟踪这些？"
- 使用 `/todos-to-issues` 转换为 GitHub issues
- 保留为代码注释以便逐步解决
- 为团队审查生成摘要报告

**重要**：我永远不会：
- 在 TODOs 中添加"由 Claude 生成"或 AI 归属
- 创建模糊或不可操作的 TODOs
- 在随机位置放置 TODOs
- 用过多的注释淹没代码

这将直接在你的代码库中创建清晰的技术债务路线图。
