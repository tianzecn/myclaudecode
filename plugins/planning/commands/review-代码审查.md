# 代码审查

我将审查你的代码以发现潜在问题。

在详细分析前让我创建检查点：
```bash
git add -A
git commit -m "Pre-review checkpoint" || echo "No changes to commit"
```

我将使用专门的子代理进行全面分析：
- **安全子代理**：凭证暴露、输入验证、漏洞
- **性能子代理**：瓶颈、内存问题、优化机会
- **质量子代理**：代码复杂度、可维护性、最佳实践
- **架构子代理**：层分离、依赖方向、可扩展性模式

我将使用 Read 和 Grep 工具检查文件，分析：
1. **安全问题** - 凭证暴露、输入验证
2. **逻辑问题** - 错误处理、边缘情况
3. **性能问题** - 低效模式、瓶颈
4. **代码质量** - 复杂度、可维护性

当我发现多个问题时，我将创建待办事项列表以系统性地解决它们。

对于每个问题，我将：
- 显示带文件引用的确切位置
- 解释问题和潜在影响
- 提供具体的修复步骤
- 按严重性和工作量排序

审查后，我将询问："为关键发现创建 GitHub issues？"
- 是：我将创建带详细描述的优先级 issues
- 仅待办事项：我将维护本地跟踪以供解决
- 摘要：我将提供可行报告

**重要**：我永远不会：
- 在提交中添加"Co-authored-by"或任何 Claude 签名
- 在 issues 中添加"由 Claude 创建"或任何 AI 归属
- 在任何输出中包含"使用 Claude Code 生成"
- 修改 git 配置或仓库设置
- 添加任何 AI/助手签名或水印
- 在提交、PR、issues 或 git 相关内容中使用表情符号

这聚焦于影响应用程序可靠性和可维护性的真实问题。
