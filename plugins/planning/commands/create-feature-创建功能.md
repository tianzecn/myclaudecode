# 创建功能

搭建新功能：$ARGUMENTS

## 当前项目上下文

- 项目结构：!`find . -maxdepth 2 -type d -name src -o -name components -o -name features | head -5`
- 当前分支：!`git branch --show-current`
- 包信息：@package.json 或 @Cargo.toml 或 @requirements.txt（如果存在）
- 架构文档：@docs/architecture.md 或 @README.md（如果存在）

## 任务

遵循以下系统化方法创建新功能：$ARGUMENTS

1. **功能规划**
   - 定义功能需求和验收标准
   - 将功能分解为更小、可管理的任务
   - 识别受影响的组件和潜在影响区域
   - 在实施前规划 API/接口设计

2. **研究和分析**
   - 研究现有代码库模式和约定
   - 识别类似功能以保持一致性
   - 研究所需的外部依赖或库
   - 审查任何相关文档或规范

3. **架构设计**
   - 设计功能架构和数据流
   - 如需要，规划数据库架构变更
   - 定义 API 端点和契约
   - 考虑可扩展性和性能影响

4. **环境设置**
   - 创建新功能分支：`git checkout -b feature/$ARGUMENTS`
   - 确保开发环境是最新的
   - 安装所需的任何新依赖
   - 如适用，设置功能标志

5. **实施策略**
   - 从核心功能开始，逐步构建
   - 遵循项目的编码标准和模式
   - 实现适当的错误处理和验证
   - 使用依赖注入并保持松耦合

6. **数据库变更（如适用）**
   - 为架构变更创建迁移脚本
   - 确保向后兼容性
   - 规划回滚场景
   - 在示例数据上测试迁移

7. **API 开发**
   - 使用适当的 HTTP 状态码实现 API 端点
   - 添加请求/响应验证
   - 实现适当的身份验证和授权
   - 记录 API 契约和示例

8. **前端实现（如适用）**
   - 遵循项目模式创建可重用组件
   - 实现响应式设计和无障碍访问
   - 添加适当的状态管理
   - 处理加载和错误状态

9. **测试实现**
   - 为核心业务逻辑编写单元测试
   - 为 API 端点创建集成测试
   - 为用户工作流添加端到端测试
   - 测试错误场景和边缘情况

10. **安全考虑**
    - 实现适当的输入验证和清理
    - 为敏感操作添加授权检查
    - 审查常见安全漏洞
    - 确保数据保护和隐私合规

11. **性能优化**
    - 优化数据库查询和索引
    - 在适当的地方实现缓存
    - 监控内存使用并优化算法
    - 考虑延迟加载和分页

12. **文档**
    - 添加内联代码文档和注释
    - 更新 API 文档
    - 如需要，创建用户文档
    - 如适用，更新项目 README

13. **代码审查准备**
    - 运行所有测试并确保通过
    - 运行代码检查和格式化工具
    - 检查代码覆盖率和质量指标
    - 对变更进行自我审查

14. **集成测试**
    - 测试功能与现有功能的集成
    - 验证功能标志正常工作
    - 测试部署和回滚过程
    - 验证监控和日志记录

15. **提交和推送**
    - 创建带有描述性消息的原子提交
    - 如果项目使用，遵循常规提交格式
    - 推送功能分支：`git push origin feature/$ARGUMENTS`

16. **拉取请求创建**
    - 创建带有全面描述的 PR
    - 如适用，包含截图或演示
    - 添加适当的标签和审查者
    - 链接到任何相关问题或规范

17. **质量保证**
    - 与 QA 团队协调测试
    - 处理发现的任何 bug 或问题
    - 验证无障碍和可用性要求
    - 在不同环境和浏览器上测试

18. **部署规划**
    - 规划功能推出策略
    - 设置监控和警报
    - 准备回滚过程
    - 安排部署和沟通

在整个开发过程中，请记住保持代码质量，遵循项目约定，并优先考虑用户体验。
