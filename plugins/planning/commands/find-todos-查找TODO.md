# 查找开发任务

我将定位代码库中所有的 TODO 注释和未完成工作标记。

我将使用 Grep 工具高效搜索带上下文的任务标记：
- 模式："TODO|FIXME|HACK|XXX|NOTE"
- 跨所有源文件的不区分大小写搜索
- 显示周围行以更好地理解

对于找到的每个标记，我将显示：
1. **文件位置**和行号
2. **完整注释**及上下文
3. **周围代码**以了解需要做什么
4. 基于标记类型的**优先级评估**

当我找到多个项目时，我将创建一个待办事项列表按优先级组织它们：
- **关键**（FIXME、HACK、XXX）：可能导致问题的事项
- **重要**（TODO）：需要的功能或改进
- **信息性**（NOTE）：可能需要关注的上下文

我还将识别：
- 引用缺失实现的 TODOs
- 需要替换的占位符代码
- 不完整的错误处理
- 等待实现的存根函数

扫描后，我将询问："将这些转换为 GitHub issues？"
- 是：我将创建适当分类的 issues
- 仅待办事项：我将维护本地待办事项列表
- 摘要：我将提供组织化的报告

**重要**：我永远不会：
- 在 issues 中添加"由 Claude 创建"或任何 AI 归属
- 在描述中包含"使用 Claude Code 生成"
- 修改仓库设置或权限
- 添加任何 AI/助手签名或水印

这有助于系统性地跟踪和优先处理未完成的工作。
