# 分析并解决 GitHub Pull Request 中的建议更改

遵循以下步骤来分析 GitHub Pull Request（PR）中的建议更改（例如，审查评论、内联建议或请求的修改）并有效地解决它们。目标是审查、理解、计划修复、应用更改、测试并更新 PR，同时保持代码质量和协作。

假设 PR 引用作为 `$ARGUMENTS` 提供（例如，PR 编号或 URL，如 `#456` 或 `https://github.com/repo/pull/456`）。

对所有与 GitHub 相关的任务使用 GitHub CLI（`gh`），例如获取 PR 详情、评论和更新 PR。

# 计划
1. 使用 `gh pr view` 获取 PR 详情
   - 获取完整的 PR 标题、描述、基础分支、头部分支、标签、受让人、审查者和任何链接的 Issue。
   - 注意当前状态（例如，打开、草稿、已合并）和任何合并冲突。

2. 获取并审查所有评论和建议
   - 使用 `gh pr comment list` 或 `gh api` 检索所有审查评论，包括内联建议（例如，在审查中建议的代码差异）。
   - 对评论进行分类：
     - **代码更改建议**（例如，"将此函数更改为使用 async/await"）。
     - **问题或澄清**（例如，"为什么选择这种方法？"）。
     - **Bug 或问题**（例如，"这在边缘情况 X 上会出错"）。
     - **样式/小问题**（例如，"重命名变量以提高清晰度"）。
     - **批准或一般反馈**。
   - 识别线程讨论或已解决/未解决的评论。

3. 识别相关依赖关系或上下文
   - 查找链接的 Issue 或其他 PR（例如，"fixes #123" 或 "depends on #789"）。
   - 检查 PR 是否是更大的 Epic、功能分支或发布的一部分。
   - 审查差异：使用 `gh pr diff` 了解 PR 中引入的更改。
   - 如果建议引用外部资源（例如，文档、标准），请验证它们。

4. 如果需要，提出澄清问题
   - 如果建议模糊，为审查者准备问题（例如，在 PR 中作为回复发布它们）。
   - 示例："您能提供预期输出的示例吗？" 或 "这需要处理国际化吗？"

5. 了解先前工作和代码库影响
   - 在代码库中搜索受影响的文件/模块（例如，使用 `git grep` 或 IDE 搜索）。
   - 审查 PR 分支中的提交历史以获取上下文。
   - 检查仓库中解决的类似过去 PR 或 Issue。

6. 深入思考如何以小型和可管理的方式解决建议
   - 将每个建议分解为可操作的修复。
   - 优先级：首先解决阻塞问题（例如，bug > 功能 > 样式）。
   - 按逻辑顺序排列修复（例如，在添加测试之前重构代码）。
   - 考虑边缘情况、性能、安全性和兼容性。
   - 起草一个计划，最小化新更改并避免引入回归。

7. 在草稿本中记录计划
   - 包括 PR 标题和链接。
   - 列出建议及建议的解决方案。
   - 确保计划结构化，便于人工或自动化执行。

# 解决
- 检出 PR 分支：使用 `gh pr checkout <PR-number>`
- 以小的增量提交应用修复
  - 对于每个建议：
    - 按计划编辑代码。
    - 使用建议的差异（如果提供）（例如，通过 GitHub UI 或手动应用内联建议）。
  - 创建清晰的提交消息：
    - 示例：`refactor(auth): update token handling per review suggestion (resolves comment in #456)`
- 如果需要，为超出范围的建议创建后续 Issue
- 回复评论：使用 `gh pr comment` 回应，例如，"已在提交 XYZ 中解决"并标记为已解决

---

# 测试
- 运行所有相关测试以验证解决方案
  - 单元测试、集成测试、端到端测试
- 确保代码通过：
  - ✅ Linting（例如，React Native 的 ESLint）
  - ✅ 类型检查（例如，TypeScript）
  - ✅ 构建检查（例如，`yarn build` 或 `npm run build`）
- 对于 React Native 特定项：
  - 在模拟器/仿真器（iOS/Android）上测试
  - 检查平台特定问题（例如，本机模块）
- 如果建议涉及 bug 或新行为，添加新测试
- 手动测试：如果自动化测试不足，记录步骤

---

# 推送
- 将更新的提交推送到 PR 头部分支
- 如果进行了重大更改，更新 PR 描述
  - 总结解决方案："已解决审查评论：修复了 auth 中的 bug，根据建议重构了 UI"
  - 引用已解决的评论或链接的 Issue
- 如果需要，重新请求审查：使用 `gh pr review --request <username>`
- 确保 PR 遵循指南：
  - ✅ 更新的标签（例如，添加 "needs-review"）
  - ✅ 无合并冲突（如果有，解决它们）
