# 智能脚手架

我将根据您的项目模式创建完整的功能结构，在会话之间保持完全连续性。

参数：`$ARGUMENTS` - 要脚手架的功能名称或组件

## 会话智能

我将在会话之间维护脚手架进度：

**会话文件（在当前项目目录中）：**
- `scaffold/plan.md` - 脚手架计划和组件列表
- `scaffold/state.json` - 已创建的文件和进度

**重要提示：** 会话文件存储在当前项目根目录的 `scaffold` 文件夹中

**自动检测：**
- 如果会话存在：恢复未完成的脚手架
- 如果没有会话：创建新的脚手架计划
- 命令：`resume`、`status`、`new`

## 阶段 1：模式发现

**强制性第一步：**
1. 检查当前工作目录中是否存在 `scaffold` 目录
2. 如果目录存在，检查会话文件：
   - 查找 `scaffold/state.json`
   - 查找 `scaffold/plan.md`
   - 如果找到，从现有会话恢复
3. 如果没有目录或会话存在：
   - 分析项目模式
   - 创建脚手架计划
   - 初始化进度跟踪
4. 在创建之前显示脚手架预览

**注意：** 始终在当前项目的 `scaffold/` 文件夹中查找会话文件，而不是 `../../../scaffold/` 或绝对路径

我将发现您的项目模式：

**模式分析：**
- 文件组织结构
- 命名约定
- 测试模式
- 导入/导出样式
- 文档标准

**智能检测：**
- 查找已实现的类似功能
- 识别架构模式
- 检测测试框架
- 了解构建配置

## 阶段 2：脚手架规划

基于模式，我将创建脚手架计划：

**组件结构：**
- 主要功能文件
- 测试文件
- 文档
- 配置更新
- 集成点

我将把这个计划写入 `scaffold/plan.md`，包含：
- 要创建的每个文件
- 要遵循的模板模式
- 集成要求
- 创建顺序

## 阶段 3：智能生成

我将生成与您的模式匹配的文件：

**模式匹配：**
- 使用您的文件命名样式
- 遵循您的目录结构
- 匹配您的代码约定
- 应用您的测试模式

**内容生成：**
- 来自现有代码的样板
- 匹配您样式的导入
- 来自您的模式的测试结构
- 您格式的文档

## 阶段 4：增量创建

我将系统地创建文件：

**执行过程：**
1. 创建目录结构
2. 生成每个组件文件
3. 添加适当的测试
4. 更新集成点
5. 在状态中跟踪每次创建

**进度跟踪：**
- 在计划中标记每个创建的文件
- 使用文件路径更新状态
- 创建有意义的提交

## 阶段 5：集成

脚手架后：
- 更新路由配置
- 添加到模块导出
- 更新构建配置
- 验证所有连接

## 上下文连续性

**会话恢复：**
当您返回并运行 `/scaffold` 或 `/scaffold resume` 时：
- 加载现有计划和进度
- 显示已创建的内容
- 从最后一个组件继续
- 保持模式一致性

**进度示例：**
```
恢复脚手架
├── 功能：UserDashboard
├── 已创建：8 个文件中的 5 个
├── 最后：components/UserStats.tsx
└── 下一个：tests/UserStats.test.tsx

继续脚手架...
```

## 实际示例

**开始脚手架：**
```
/scaffold UserProfile          # 创建用户配置文件功能
/scaffold "auth module"        # 创建身份验证模块
/scaffold PaymentService       # 创建支付服务
```

**会话控制：**
```
/scaffold resume    # 继续现有脚手架
/scaffold status    # 检查已创建的内容
/scaffold new       # 开始新的脚手架
```

## 安全保证

**保护措施：**
- 创建前预览
- 增量文件生成
- 模式验证
- 集成验证

**重要提示：** 我绝不会：
- 覆盖现有文件
- 破坏现有导入
- 添加 AI 归属
- 不遵循模式创建

## 我实际上会做什么

1. **深入分析** - 了解您的模式
2. **完整计划** - 映射所有组件
3. **智能生成** - 匹配您的样式
4. **精确跟踪** - 完美连续性
5. **无缝集成** - 连接一切

我将在会话之间保持完全连续性，始终从我们离开的地方恢复，并应用一致的模式。
